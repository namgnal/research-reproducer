# 从论文到可验证实验

## 最小研究协议

按目标选取需要的字段，不为每篇论文套同样的研究问题：

- 来源：原文版本、对应章节/公式/表格、官方实现的 commit 和数据版本。
- 主张：可以被结果推翻的陈述；把“某数据集上指标提高”与“提出一种算法”分开。
- 复现范围：完整、部分或机制；记录原设置与本次设置的差异。
- 方法：基线、候选变化、数据划分、评价指标、随机性和资源预算。
- 验收：实现检查、行为检查和结果条件分别列出；阈值由原文还是本次实验定义。
- 证据：运行命令、代码/数据指纹、日志、预测或中间产物、失败记录。

例如，公式实现正确不代表其最终任务效果已经复现。用合成随机输入验证注意力缩放只支持该机制在声明分布下的性质，不能外推到机器翻译性能。

## 可比性与研究质量

开发集用于选择，确认集用于一次性验证冻结的选择。重复运行需要与任务相关：随机训练应记录训练种子；数据划分变化应记录划分种子；系统性能实验还需控制缓存、并发、硬件和负载。不要把共享同一数据集的多随机种子称为独立数据集证据。

先冻结评价规则，候选实现不能通过改动评估器降低任务难度。采用自报指标时让独立评估器从预测或输出重新计算，并抽查输入与输出对应关系。助手提供的哈希校验主要检测漂移，不阻止拥有同等文件权限的恶意程序。

采用明确的对照或消融解释改动；若同时改动多个因素，结论只覆盖组合效果。探索发现需要确认，不能将搜索中最佳一次的分数当作稳定提升。复杂统计检验按样本结构选用成熟工具，内置均值/标准差/配对差值不是显著性检验。

失败、未改善和证据不足均属于有效研究结果。排查失败可以形成子试验，但应计入运行预算并保留原记录。不能用“未取到指标”填 0 来制造改善。

在执行前确定证据粒度和存储成本。确定性合成输入可保存生成器、版本、种子与内容指纹，数值核查则保留所需原始输出或关键中间量；真实数据须有可获取的位置和固定版本。保存完整张量时，将候选、重复和额外复跑的副本一起估算。执行器外的审计或复跑另列时间与进程预算，不把这些费用遗漏在主试验计时之外。

## 独立复跑与分层验收

受 PaperBench 的提交、独立执行与评分分离启发，优先让评分依据落在真实执行结果上。代码存在、代码可运行和结果满足条件是不同层级。

必要时在新的目录或用户已授权的干净环境重建依赖并复跑。若仅在原机器的新目录验证，就如实称为“同环境独立目录复跑”。没有独立进程、没有第二个执行者、没有重新执行时，不使用相应的验证措辞。

逐项结论可写：范围内得到支持、范围内未获支持、证据不足、未验证。保留实际数值和条件，不将本地 rubric 包装成 PaperBench 官方分数。
